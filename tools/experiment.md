# tools/experiment.md — 方法实验协议（A/B 对比 · 稳定性主线）

> **定位**：测"方法"，不测"模型"、不测"审美"。回答的问题只有一个——**哪个工作流 / 提示词样式 / 参数策略，对最终产出的稳定性贡献更大**。
> 与 verifier.md 的分工：verifier = 单次出图的事后校验 + 案例沉淀；experiment = **受控方法对比**（事前设计 + 批量执行 + 统计结论），结论写回 ideation / presets / params。
> 依据：2026-10 调研三连（变量体系 / 市面测评 / 客观性可行性 / 提示词与工作流生态）+ 用户方法论（环节拆解 · 变量隔离 · 抽卡-锚定-展开）。市面"以方法为中心测稳定性"的基准是真空缺——本协议是差异化落点。

## 1. 三条原则（写在最前，一切实验的前提）

1. **环节拆解**：把原本并在一起的环节拆开。凡是"可以确定性完成"的环节（建模、构图、条件图、参考图、版本锁定）一律前置成步骤，不留给生成随机性。例：生图 → 建模打底 → 导出条件图 → 再生成，就是"把交给模型生成的内容定好"。
2. **变量隔离**：把不可控变量隔在生成之外。隔离强度排序（已调研修正）：
   `条件图 / ControlNet（结构）> 模型版本 + 参考图（风格）> 提示词（语义）> seed（最弱，仅限定随机窄带，不承诺复现）`
   —— diffusers 官方"同 seed 也不保证复现"，MJ 官方 seed"影响最小"。禁止把 seed 当稳定性承诺。
3. **抽卡-锚定-展开**（AIGC 业内通用循环）：
   - 探索期（抽卡）：放开随机，批量生成，捞"对味"的感觉；
   - 锚定期：锁定一张基准图 → 落 `style_anchor` / `camera_ref` 资产 + 固定模型版本与种子；
   - 展开期：以锚定图为参考 / 条件，多参批量生成新内容。
   —— 稳定性不是"每次一样"，是"锚定之后可预期"。

## 2. 实验卡片（promptfoo 形态的 YAML）

每次实验 = 一张卡片，存 `experiments/`（产品仓）或用户资产库 `_experiments/`：

```yaml
experiment:
  id: exp.2026-10-05.ruined-city-blockout   # 点分命名
  question: 白模打底 vs 纯提示词，对复杂场景构图稳定性的影响   # 一句话实验问题
  task: 末日古树侵蚀城市（场景需求原文）      # 真实任务，不造作
  method_a:
    name: 纯提示词
    workflow: [t2i-direct]
    params: {prompt_style: fived-段式, cfg: 6.5}
  method_b:
    name: 白模打底
    workflow: [model-blender, camera_ref, img2img]
    params: {prompt_style: 五段式, cfg: 6.5, ref_strength: 0.6}
  controls:                                # 受控条件：只允许被测方法不同
    model: doubao-seedream-4-5-251128      # 锁模型版本（日期快照）
    seed: fixed-20261005                   # 锁种子（限随机窄带）
    task: same                             # 同需求
    n: 5                                   # 每组生成张数（小样本起步）
  metrics:
    pass_k: 3        # 稳定性主指标：同任务复跑 k 次、通过判定标准 ≥ 的比例（τ-bench pass^k 借鉴）
    structure_fail_rate: true   # 结构崩坏率（L1 硬断言统计）
    consistency: true           # 主体/系列一致性
    composition_ok: true        # 构图达标率（比例/巨物感/景别断言）
    content_dist: lpips+dino    # 内容面相对距离（L2）
    style_dist: csd+gram        # 风格面相对距离（L2，需过门禁）
  gate:
    min_top1_hit: 0.7   # 自动第一名命中人工 ≥70% 才全自动；<60% 只出候选
    human_check: 0.2    # 每批人工抽检比例
    tie_threshold: 0.05 # 总分差小于此 → 转人工
```

## 3. 三层判分（可执行版本）

| 层 | 内容 | 谁执行 | 权限 |
|---|---|---|---|
| L1 确定性断言 | 参数合规 / 对象计数 / OCR / 尺寸比例 / 翻车率 | 规则复算，全自动 | 一票否决（不过即淘汰） |
| L2 相对排序 | 内容面（LPIPS + DINO）· 风格面（CSD 主 + Gram 辅）距离 | 神经网络计算 | 只排座次；**上线前过门禁**：黄金集上与人工 Spearman ≥ 0.5 且 top1 命中 ≥ 0.7 |
| L3 人工抽检 | 每批 ≥20%；记录"因内容 / 因风格 / 因整体感觉"选择 | 人 | 唯一最终裁定；归因反馈用于迭代 L2 权重 |

> 硬边界：任何把 IQA / 感知距离 / 审美模型当"绝对客观真理"直接输出"这张最好"的做法，本协议禁止。L2 只能输出"相对更接近参考"，不能输出"质量分"。

## 4. 首批可测方法变量（候选池，按需取）

| 方法变量 | A 组 | B 组 | 产出什么结论 |
|---|---|---|---|
| 前置工作流 | 纯提示词直出 | 建模打底 → 条件图 → 再生成 | "打底对复杂构图的有效性"，写回 ideation B 循环 |
| 提示词样式 | 五段式（主体/环境/风格/光线/质量） | 自由描述 / 关键词堆砌 | 样式对构图达标率影响，写回 prompt_structure |
| 描述语言 | 关键词式（逗号分隔） | 自然语言长句（按模型分组） | 模型族适配（Flux 类偏好长句，质量词堆砌随模型失效） |
| 参考策略 | 单风格参考 | 内容参考 + 风格参考分离 | ref_type 用法校正，写回 params.md |
| 模型版本 | 旧快照 | 新快照 | 版本决定默认值（步数/CFG/分辨率桶），更新 base_model 语义 |

## 5. 执行步骤（六步）

1. **设计**：填实验卡（question / methods / controls / metrics / gate）。
2. **受控跑批**：A/B 各生成 n 张，全量记录变量（模型版本 / seed / 参数 / 参考图 / 时间）。
3. **L1 硬断言**：全自动过滤翻车（淘汰不计数，淘汰率本身也是指标）。
4. **L2 排序**：内容 + 风格距离，过门禁才生效。
5. **L3 抽检**：人工抽 20%，记录归因；平票（差 < 0.05）转人工。
6. **统计与写回**：pass^k、崩坏率、达标率 → 结论写回（见 §6），附实验卡归档。

## 6. 结论写回（进化回路的"食物"）

- **ideation.md**：环节拆解的有效做法 → 升级"可选"为"推荐"（如白模打底）。
- **presets/ 预设卡**：方法 - 任务匹配实证 → 调默认档 / 新增预设。
- **params.md 语义库**：模型族适配、参数 - 方法关联 → 补"调优方向"与"常见坑"。
- **prompt 资产库**：实验产出的有效提示词 → 沉淀为 kind=prompt 资产（带 source / platform / verified 字段）。

**质量闸口**（沿用 verifier.md 第 4 步并加强）：
- 结论至少 **2 个同向案例**（不同任务同方法）支撑才允许写回；单案例只进"待观察"。
- 跨平台结论禁止混用（即梦的结论不能直接写进 ComfyUI 卡，除非语义层确认）。
- pass^k 用 k≥3 复跑，单次随机不当事。

## 7. 校验清单（扣分项）

- [ ] 实验卡 controls 是否锁齐（模型版本 / seed / 任务 / 组数）？
- [ ] 是否只允许一个方法变量差异？
- [ ] L2 指标是否过了门禁（Spearman ≥ 0.5）才参与排序？
- [ ] L3 抽检 ≥ 20% 且归因（内容/风格）已记录？
- [ ] 结论是否有 ≥2 同向案例支撑、是否跨平台混用？
- [ ] seed 是否被表述为"限随机窄带"而非"复现保证"？
