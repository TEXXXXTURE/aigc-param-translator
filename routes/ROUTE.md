## 匹配规则

0. **主入口前置**：所有需求先走 `ideation.md` 三循环（风格锚 → 构图 → 灯光），三循环决策完成后才进入本表匹配；预设卡只作档位基底，不替代思路拆解。
1. **按最强特征匹配**：需求同时命中多张卡时，取"主体目标"最贴近的一张，其余特征作为覆盖项写入方案（如"赛博朋克风的电商主图" → 01 为基底 + 02 的风格档覆盖）。
2. **参考素材优先**：用户已提供参考图 / LoRA / 角色图时，预设档位降级为"参考优先"模式，对应参考类参数（ref_strength / lora_weight / controlnet）以参考素材为准。
3. **平台差异**：预设档位基于原子参数语义层；落地到具体平台时查 `shared/glossary.md` 映射，未映射标"待补"。**预设式平台跳过原子档位**，直接输出三循环决策 + 五段式提示词 + 平台档位（质量 / 张数 / 画幅）。
4. **未知即兜底**：未命中一律走 00-default，并在方案 meta 中注明"未命中预设，已按通用档位生成，可指定场景细化"。

## 新增预设

用户常做某类需求时，按 `presets/` 现有卡的格式新建（适用特征 / 默认档位 / 原子参数建议 / 可覆盖声明 / 常见坑 / 校验区），经用户确认后写入。
