# 04 · 角色设计卡

> 用途：角色设计 / 人设图 / 角色三视图 / 角色一致性 / 立绘。核心诉求：**同一个角色反复出现不崩脸**。

## 适用需求特征

- "角色设计""人设""三视图""立绘""角色一致性"
- "同一个角色出多张""漫剧/连载角色资产"

## 默认档位

| 维度 | 档位 |
|---|---|
| 模型 | 角色一致性优先选择支持多参考的平台能力（即梦多图参考 / 可灵 multiImageToImage / 豆包 Seedream 多图输入 / SD 系 + LoRA） |
| 采样器 | DPM++ 2M Karras |
| 步数 | 28–32 |
| CFG | 6–7（人像区间） |
| 分辨率 | 1:1 或 3:4（立绘竖版） |
| 种子 | 固定种子 + 资产引用共同锁定 |
| 提示词结构 | 角色设定卡：外貌（五官/发型/体型）+ 服饰（款式/配色/材质）+ 特征（胎记/配饰/标志物）+ 姿态 |
| 资产策略 | **角色资产优先**：角色参考图（正面+侧面+背面）→ 进参考/训练角色 LoRA；无资产时提示词兜底但告知一致性风险 |

## 原子参数建议

```json
{
  "sampler": "DPM++ 2M Karras",
  "steps": 30,
  "cfg": 6.5,
  "ref_type": "content",
  "ref_strength": 0.8,
  "assets": ["character-sheet"],
  "lora_weight": 0.6
}
```

## 可覆盖声明

- 用户有角色图（哪怕一张）：参考优先，ref_strength 0.7–0.9；多角度图更好（三视图 → 最强资产）。
- 用户要求连载/漫剧级一致性：建议升级为**角色 LoRA**（走 `knowledge/assets.md` 的 train_lora 插件接口，接现成训练实现），权重 0.5–0.7。
- 无任何角色资产：只能用提示词描述，方案必须明确标注"无资产，一致性风险高，建议先建角色资产"。

## 常见坑

- 只靠提示词描述角色 → 出图每次换脸，连载必崩。
- 参考权重过高（>0.95）→ 构图姿态被锁死，换动作困难。
- 角色 LoRA 权重过高 → 过拟合，表情/姿态僵化。

## 校验区（扣分项）

- [ ] 是否给出角色资产策略（有图 → 参考；长期 → LoRA）
- [ ] 无资产时是否明确标注一致性风险
- [ ] 设定卡是否含"标志物"（可复现的锚点，如胎记/配饰）
- [ ] 是否区分"参考内容"与"参考风格"（角色必须是 content）
