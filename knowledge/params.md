# 参数语义库（解释器底座）

> 解释器唯一事实底座。每个原子参数维护五要素：**是什么 / 影响什么 / 调优方向 / 典型范围 / 常见坑**。
> 机器可校验的精简版见 `schema/params.schema.json`（registry），本文件是面向使用者与 Agent 的完整叙述。
> 原则：未核实的内容标"待确认"，不编造；平台差异见 `shared/glossary.md`。

## 模型族

### base_model · 模型基座
- **是什么**：生成所基于的扩散模型（SD1.5 / SDXL / FLUX / doubao-seedream / 即梦 4.0 / 可灵 / 混元…）。它决定风格底子、质量上限和生态兼容性。
- **影响什么**：写实/动漫的画风底盘、出图质量上限、可用的 LoRA 与插件生态。
- **调优方向**：写实向选 SDXL/FLUX/doubao-seedream 系；动漫向选动漫微调模型；拿不准用平台默认写实模型起步。
- **典型范围**：按平台可用列表选择。
- **常见坑**：跨基座混用 LoRA（SD1.5 的 LoRA 用在 SDXL 上）会失效或报错；误以为"最新=最适合"，忽略风格匹配。**注意 base_model 与 model_version 分离**（基座是族，版本是具体快照，见下条）。

### model_version · 模型版本快照
- **是什么**：模型的具体版本（如 `doubao-seedream-4-5-251128` 这类日期快照），独立于 base_model 基座。
- **影响什么**：**版本直接决定默认值——步数 / CFG 档 / 分辨率桶**；跨版本套用参数可能已失效（蒸馏/快模式会改变 CFG 与步数语义）。
- **调优方向**：翻译时锁定具体版本快照，默认值从该版本文档读取；拿不准用平台最新稳定版。
- **典型范围**：按平台可用版本列表。
- **常见坑**：把版本塞进 base_model 导致默认值错乱；旧版本参数套新版本失效（如升级到蒸馏版后 CFG 语义从 4–12 变成固定 1）。

### model_variant · 模型变体/风格版
- **是什么**：同一基座下的风格化版本（如水墨版、动漫版、胶片版）。
- **影响什么**：在同一基座内决定具体画风。
- **调优方向**：按需求风格选择；不确定留平台默认。
- **典型范围**：按平台可用列表选择。
- **常见坑**：变体名记错导致风格完全不对。

## 生成控制

### sampler · 采样器
- **是什么**：扩散去噪的数值求解器，决定每一步如何从噪声走向图像。
- **影响什么**：收敛速度、细节锐利度、随机纹理；相同提示词下不同采样器风格有别。
- **调优方向**：通用求稳 `DPM++ 2M`；要更锐利的细节 `DPM++ SDE`（更慢）；动漫场景 `Euler a` 常更顺手。
- **典型范围**：枚举见 schema（**不含调度器后缀**——A1111 的 `DPM++ 2M Karras` 是"采样器+调度器"的 UI 串名，翻译时拆为 sampler=DPM++ 2M + scheduler=Karras）；目标平台无对应项用平台默认。
- **常见坑**：换采样器后效果大变却忘记同步调整步数；**把 UI 串名当单一采样器名**——ComfyUI 里 sampler 与 scheduler 是两个独立下拉。

### scheduler · 调度器
- **是什么**：步数调度曲线（每步噪声如何衰减），与采样器解耦的独立参数。
- **影响什么**：收敛节奏与纹理风格；同采样器配不同调度器效果有别。
- **调优方向**：通用 `normal` / `karras`；快速收敛 `exponential`；SGM 系模型用 `sgm_uniform`。
- **典型范围**：normal / karras / exponential / sgm_uniform / ddim_uniform。
- **常见坑**：采样器与调度器不匹配报错；A1111 的 `DPM++ 2M Karras` 是 UI 串名，须拆开翻译。

### steps · 步数
- **是什么**：去噪迭代次数。
- **影响什么**：过少细节不足、结构不稳；过多收益递减且更慢。
- **调优方向**：写实 28–35；动漫 25–30；概念大场景 30–35。
- **典型范围**：20–40（通用）；<15 易崩，>40 收益极小。
- **常见坑**：把步数当"万能调节"——方向错了加步数救不回来；高步数配差采样器反而更脏。

### cfg · CFG 引导强度
- **是什么**：模型遵循提示词的强度。数值越高越贴提示词。
- **影响什么**：贴合度与自然度的平衡。过高 → 过饱和、轮廓生硬；过低 → 主体散架、提示词失效。
- **调优方向**：**按基座分档（2026-10 调研修正，不可跨基座套用）**：

  | 基座 | 典型档 | 备注 |
  |---|---|---|
  | FLUX 系（dev/schnell） | 2.5–3.5 | 蒸馏版（turbo 等）CFG=1，不暴露引导档 |
  | SD1.5 | 7–12 | 常见 7；写实 5–6.5，白底产品图可更低防塑料感 |
  | SDXL | 4–7 | 常见 5–7 |
  | Seedream / 即梦 / 可灵 | 平台封装 | 无裸 CFG，用"提示词强度/参考强度"近似 |

  通用直觉：结果"散"提档，"塑料感/过饱和"降档。
- **典型范围**：按基座分档（上表）；>15 视为异常需复核。
- **常见坑**：**FLUX 套用 SD1.5 的 7–12 直接过饱和/崩坏**；蒸馏快模式（turbo/lightning/lcm）CFG 语义整体改变、常固定为 1；>12 色彩过饱和轮廓生硬（SD1.5 语境）；<3 主体散架；白底产品图过高出塑料质感。

### seed · 种子
- **是什么**：随机噪声的初始种子。同参数 + 同种子 → 可复现结果。
- **影响什么**：控制每次生成的随机性；是迭代对比与系列一致性的基石。
- **调优方向**：迭代时固定种子、单改一个参数做 A/B 对比；构图方向满意后再微调；换构图就换种子。
- **典型范围**：任意整数；null = 随机。
- **常见坑**：不固定种子导致无法对比参数效果；误以为种子决定画面风格（它只决定噪声起点）。

### batch_size · 批量生成数
- **是什么**：一次生成几张供挑选。
- **影响什么**：命中率与成本成正比。
- **调优方向**：初筛 4–8 张广撒网；锁定方向后回 1–2 张精修。
- **典型范围**：1–8。
- **常见坑**：批量≠多样性（同种子批量可能高度雷同）；API 场景批量费用翻倍。

## 画布

### width / height · 宽高
- **是什么**：画布像素尺寸，共同决定构图比例。
- **影响什么**：细节总量、构图骨架、平台是否裁切。
- **调优方向**：**优先用平台预设分辨率桶（见 size_bucket）**；ComfyUI 类自由像素平台才直接填宽高，按载体比例换算（1:1 / 4:5 / 16:9…）；套图统一比例。
- **典型范围**：512–1536（平台默认优先）。
- **常见坑**：小图硬放大只会糊；宽高比超出平台上限被裁切；**在枚举桶平台（Qwen/混元/Seedream）填自由像素会被吸附变形**。

### size_bucket · 分辨率桶
- **是什么**：平台预定义的画布尺寸档（Qwen/混元/Seedream 都是枚举桶，不是自由像素）。
- **影响什么**：决定构图比例与细节量；枚举桶平台填自由像素会被吸附或报错。
- **调优方向**：优先选平台预设桶（如 1664×928、1024×1024、896×1152…）；ComfyUI 类才用自由像素 width/height。
- **典型范围**：按平台预设档选择（常见：1024×1024 / 1664×928 / 1216×832 / 1344×768 / 896×1152 / 768×1344 / 832×1216 / 1536×640 / 640×1536）。
- **常见坑**：自由像素在枚举桶平台被吸附变形；size_bucket 与 aspect_ratio 矛盾（桶已隐含比例，两者以桶为准）。

### aspect_ratio · 画幅比例
- **是什么**：长宽比，独立于像素值的构图维度。
- **影响什么**：构图骨架——海报竖版、世界观横版、社媒 4:5。
- **调优方向**：按载体定；系列图固定一个比例。
- **典型范围**：1:1 / 4:5 / 3:4 / 2:3 / 9:16 / 16:9 / 3:2 / 2.35:1。
- **常见坑**：比例与像素值矛盾（如 16:9 配 1024×1024）；海报误用 1:1 构图平庸。

### hires_fix · 高清修复
- **是什么**：先生成低分辨率、再放大重绘，改善高分辨率下的结构细节。
- **影响什么**：高分辨率下减少人体/细节崩坏；增加耗时。
- **调优方向**：目标分辨率 > 基础分辨率 1.5 倍时开启；常规 1:1 不需要。
- **典型范围**：开启 / 关闭。
- **常见坑**：放大重绘幅度（denoise）过高会把脸改样；小图硬开纯增加耗时。

### upscale_scale · 放大倍数
- **是什么**：最终分辨率相对初始的放大倍数。
- **影响什么**：输出清晰度与耗时。
- **调优方向**：常规 2 倍；宣传物料 3–4 倍配合放大模型/重绘。
- **典型范围**：1.5–4。
- **常见坑**：纯放大不重绘只会虚化；倍数过高且无放大模型时纹理脏乱。

### denoise · 重绘幅度
- **是什么**：图生图/放大时保留原图多少、重绘多少（0=原样，1=完全重画）。
- **影响什么**：改动强度。控制放大、改光影、重构图。
- **调优方向**：微调 0.2–0.35；改光影 0.4–0.55；重构图 0.6+；放大修复常用 0.3–0.4。
- **典型范围**：0.2–0.6。
- **常见坑**：放大时 denoise 过高人物变样；想保留细节却用 >0.5 全糊掉。

## 提示词

### prompt · 正向提示词
- **是什么**：描述想要画面的文本，最重要的语义输入。
- **影响什么**：可用性取决于结构（见 prompt_structure 五段式）。
- **调优方向**：按五段式组织：主体 → 环境 → 风格 → 光线 → 质量词；需求里的具体细节全部保留，不抽象化。
- **典型范围**：50–150 词（平台上限不同）。
- **常见坑**：只写抽象词（高级/好看/宏大）模型无法定位；堆砌无关质量词稀释注意力。

### negative_prompt · 负面提示词
- **是什么**：明确不要出现在画面里的内容。
- **影响什么**：压低指定问题出现概率（不是绝对屏蔽）。
- **调优方向**：通用基线 + 按体裁追加（写实+塑料感/过度锐化；动漫+写实感/3D 渲染）。
- **典型范围**：5–15 项关键词。
- **常见坑**：负面词只能降概率不能绝对禁止；负面词过多干扰主体生成。

### prompt_structure · 提示词结构
- **是什么**：提示词的段落组织约定（写作规范，不是独立数值参数）。
- **影响什么**：结构清晰 → 模型理解准；乱序 → 重点丢失。
- **调优方向**：按预设卡的结构写；有参考素材时可简化描述。
- **典型范围**：主体/环境/风格/光线/质量词 五段式。
- **常见坑**：把全部信息压成一句话；权重语法写错（括号不配对）导致解析失败。

### tag_weight · 权重语法
- **是什么**：强调某词组的语法，如 `(word:1.2)`。
- **影响什么**：放大/缩小某概念对画面的影响。
- **调优方向**：关键特征 1.1–1.3；次要元素 0.8–0.9；少用 >1.5。
- **典型范围**：0.5–1.5（超出易失衡）。
- **常见坑**：滥用高权重导致过饱和/堆叠；部分平台不支持该语法。

## 参考与引导

### reference_images · 参考图
- **是什么**：作为内容或风格锚点的输入图片列表。
- **影响什么**：角色/产品/画风一致性的最强手段，比提示词稳定。
- **调优方向**：角色/产品用 content 参考；画风用 style 参考；多图各司其职、按类分工。
- **典型范围**：0–10 张（平台上限不同）。
- **常见坑**：参考类别混用（风格图当角色图）导致崩坏；参考图过多反而让模型自由发挥。

### ref_strength · 参考强度
- **是什么**：生成结果贴合参考图的程度。
- **影响什么**：越高越像参考（含构图），越低越自由。
- **调优方向**：内容参考 0.7–0.9；风格参考 0.5–0.75；多参考取中。
- **典型范围**：0.4–0.9。
- **常见坑**：>0.95 构图姿态被锁死；过低角色/产品特征漂移。

### ref_type · 参考类型
- **是什么**：参考图承担的角色——style（画风/氛围）还是 content（主体/角色/产品）。
- **影响什么**：类型定错则参考效果完全相反（角色图误设为 style → 每次换脸）。
- **调优方向**：角色/产品/地标 = content；画风/色调 = style；复杂多图 = multi 且按类分工。
- **典型范围**：style / content / multi。
- **常见坑**：角色图当风格图用；多图不分类，模型混淆主次。

### controlnet_type · ControlNet 类型
- **是什么**：用额外条件图（线条/深度/姿态/分割）约束画面结构。
- **影响什么**：精确控制构图、动作、版面。
- **调优方向**：保形用 lineart/canny；场景空间用 depth；人物动作用 pose；老图修复用 tile。
- **典型范围**：lineart / canny / depth / pose / seg / scribble / tile。
- **常见坑**：需要对应预处理器（没跑预处理直接报错）；权重过高线条生硬。

### controlnet_weight · ControlNet 权重
- **是什么**：条件图对生成的约束强度。
- **影响什么**：越高越贴条件图（可能僵硬），越低越自由（可能跑形）。
- **调优方向**：0.6–0.9 通用；精确对位可到 1.0+；要留余地 0.5。
- **典型范围**：0.5–1.2。
- **常见坑**：>1.3 结构生硬不自然；与参考强度同时使用互相打架。

### controlnet_range · ControlNet 生效步范围
- **是什么**：条件约束在多少比例的去噪步中生效（如 0.0-0.6 = 前 60% 步）。
- **影响什么**：前段生效定结构，后半程放开保自然。
- **调优方向**：结构严控 0.0-1.0；要自然感 0.0-0.6。
- **典型范围**：0.0-1.0 或 0.0-0.6。
- **常见坑**：范围设错导致约束失效或过度僵硬。

## 个性化

### lora · LoRA 列表
- **是什么**：叠加的 LoRA 模型列表（角色/风格/概念）。
- **影响什么**：把特定角色/画风/概念注入生成，一致性最强手段之一。
- **调优方向**：按目标选；多 LoRA 注意基座兼容与权重平衡。
- **典型范围**：0–3 个。
- **常见坑**：基座不匹配直接报错；多 LoRA 叠加互相干扰。

### lora_weight · LoRA 权重
- **是什么**：LoRA 对结果的影响强度。
- **影响什么**：过高过拟合（僵化/特征炸），过低特征不明显。
- **调优方向**：角色 0.5–0.7；风格 0.6–0.8；微调 0.3–0.5。
- **典型范围**：0.3–0.9。
- **常见坑**：>1.0 角色表情姿态僵化；低权重下期望的资产特征没出现。

### lora_triggers · LoRA 触发词
- **是什么**：激活 LoRA 所需写入提示词的触发词（若有）。
- **影响什么**：不写触发词 LoRA 可能完全不生效。
- **调优方向**：从 LoRA 说明读取，原样写入提示词。
- **典型范围**：1–3 个词。
- **常见坑**：漏写触发词导致 LoRA 无效；改写过导致特征偏移。

### ip_adapter_weight · IP-Adapter 权重
- **是什么**：参考图特征注入强度（内容/风格通用）。
- **影响什么**：把参考图的语义特征（角色/画风）注入生成，比提示词强、比 LoRA 轻。
- **调优方向**：内容 0.7–0.9；风格 0.5–0.7；微调 0.3。
- **典型范围**：0.3–0.9。
- **常见坑**：权重过高构图被参考图绑架；与 LoRA 同时使用需降档防冲突。

## 使用规则

1. **解释必须绑定方案里的具体改动项**：不解释方案外的参数。
2. **快档**：只给"值 + 一句话为什么"；**全档**：给完整五要素叙述。
3. **未核实标"待确认"**：平台特有参数（如即梦参考强度、可灵动态参考）若未在 glossary 映射，明确标"待补/待确认"。
4. **本库随进化回路更新**：tools/verifier.md 沉淀的失败案例补进对应参数的"常见坑"。
