# 执行层三分支：路由与指引规范

> 解决"小厂不接受 Agent API 操作、基本只能靠手动"的现实：人必须懂参数。三分支共用同一份调参方案，解释知识只维护一份。
> **路由写死，不让模型临场判断**：有 API/MCP → A；无 API 但可读屏 → B；否则或用户选学习模式 → C。

## 0. 路由规则（写死）

```text
是否有 API / MCP 可直连出图？
  ├─ 是 → 分支 A（API 直连）；失败 → 转 B/C
  ├─ 否，但 Agent 可读屏操作目标软件（ComfyUI 本地 / 网页端）→ 分支 B（computer use）
  └─ 否，或用户明确选"学习模式 / 手动操作" → 分支 C（人工指引）
```

- 路由判定不看模型心情：按上述规则机械执行。
- 用户可随时要求降级：A → B → C，永不反向升级。
- 三分支的输入都是同一份调参方案（schema/plan.schema.json 的产物）。

## 1. 分支 A · API 直连

**适用**：火山方舟 Seedream API / ComfyUI MCP / 即梦、可灵等开放 API。

**流程**：
1. 按 `shared/glossary.md` 把方案 params 映射为平台 API 字段（未映射标"待补"，不假装）。
2. 组装请求：prompt / negative_prompt / 尺寸 / 参考图 URL / 数量 / 种子等。
3. 提交 → 拿图 → 交给 `tools/verifier.md` 校验。
4. 可批量、可回放：方案可存为模板，换种子/换图批量执行。

**失败处理**：API 拒绝（参数非法）→ 回到校验环节修正；网络/配额问题 → 转 B 或 C 并说明。

**操作日志**：请求参数摘要 + 返回结果 + 校验结论（沉淀为成功/失败案例）。

## 2. 分支 B · computer use 读屏操控

**适用**：无 API，但 Agent 能读屏操作目标软件（ComfyUI 本地界面、即梦网页端等）。

**流程**：
1. 方案 → GUI 操作序列：把每个参数槽位翻译成"在界面的哪里、输入什么"。
2. 读屏定位：截屏识别界面元素（输入框/滑杆/下拉）。
3. 逐步执行：一次一个动作（输入值 / 拖滑杆 / 点按钮）。
4. **每步读屏验证**：该步是否生效（值是否进入、报错是否出现）；任一步失败 → 修复或回退 C。

**操作日志（必须记录，反哺分支 C）**：
- 步骤序号 / 动作描述 / 界面截图 / 结果（成功/失败/报错原文）/ 实际生效值。
- 日志沉淀为"指引库"条目，供分支 C 直接复用。

**约束**：
- 禁止在未读屏确认时连续盲点；失败两次即回退 C，不硬闯。
- 界面变化导致定位失效时，重新截图再定位，不靠记忆坐标。

## 3. 分支 C · 人工指引（永不失效的兜底）

**适用**：无 API 且不可读屏；或用户选"学习模式"（想边做边懂）。

**配方**：调参方案 × 界面映射 × 参数语义库 → 产出**指引**：

对每个改动项给出四要素：
- **在哪**：目标平台界面的哪个位置（如"左侧第二个面板 → 采样器下拉"）。
- **做什么**：选择/输入什么值（照抄方案值即可）。
- **填什么**：提示词正文、负面词、参考图路径等文本类内容的原文。
- **预期看到什么**：改完这一项，画面应该往哪个方向变化（用于自我确认）。

**输出格式（可照做）**：

```text
步骤 1｜采样器
  在哪：采样器下拉菜单
  做什么：选择 DPM++ 2M Karras
  预期：线条更干净，纹理更平滑
步骤 2｜CFG
  在哪：CFG Scale 输入框
  做什么：填入 6（从默认 7 降到 6）
  预期：色彩不过饱和，更接近自然
  （为什么：写实区间 5–6.5；你要求的"白底质感"需要压低 CFG 防塑料感 —— 见参数语义库 cfg）
```

**快档**：只给"在哪/做什么/填什么"三步表 + 预期，解释异步补（用"学习模式"追问时再给全档）。
**全档**：上述四要素 + 每个参数的完整五要素解释。

**学习模式附加**：每完成一步，追加"为什么这样调"（绑定该参数语义条目），让使用者边做边懂。

## 4. 两腿互为养料

- 分支 B 的操作日志（步骤 + 截图 + 结果）→ 沉淀为指引库 → 分支 C 直接引用，指引质量随使用次数提升。
- 分支 C 的"预期看到什么"若被用户反馈不符 → 回写参数语义库的"常见坑"，进入进化回路。

## 5. 界面映射维护

- `shared/glossary.md` 维护"原子参数 ↔ 平台界面/API 字段"映射；新增平台或界面改版时更新。
- 未映射项：指引中明确标"待补"，不编造位置。
